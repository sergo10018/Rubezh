## 2. Как выглядит процесс создания игры

```
Концепт → Пре-продакшн → Прототип → Вертикальный срез → Альфа → Бета → Запуск → Live-ops
```

| Этап | Суть | Результат |
|---|---|---|
| **Концепт** | Идея, жанр, аудитория, столпы (pillars) | Документ концепции (у вас уже есть) |
| **Пре-продакшн** | GDD, техническая архитектура, объём MVP, пайплайны | GDD, TDD (тех. дизайн), бэклог |
| **Прототип** | «Серый бокс»: проверяем, весело ли стрелять и выживать | Играбельная сборка на кубах |
| **Вертикальный срез** | Небольшой кусок игры в финальном качестве | Демо, которое можно показать людям |
| **Альфа** | Все ключевые системы есть, контент неполный | Закрытые тесты |
| **Бета** | Контент готов, балансировка, оптимизация, нагрузка | Открытый тест |
| **Запуск / Live-ops** | Ранний доступ, обновления, новые регионы-главы | Работающий проект |

### 2.1 Честно о масштабе

Классическая MMORPG (тысячи игроков в одном бесшовном мире) — это работа студий из 50–300 человек на 4–7 лет. Команде из 5 человек + ИИ нужно сузить задачу, **не теряя идеи**:

**Предлагаемая модель — «MMO-lite» / persistent online shooter:**
- персонаж, инвентарь, деньги, репутация, гильдии, рынок — **постоянные** и хранятся в общем бэкенде;
- мир разделён на **зоны** (поселение-хаб, локации Пограничья), каждая зона — отдельный выделенный сервер UE5 на 32–100 игроков;
- территориальная война идёт **поверх зон**: объект (завод, насосная станция) принадлежит гильдии в базе данных, а бой за него — событие на сервере зоны;
- это ближе к Escape from Tarkov / DayZ / Albion по архитектуре, чем к WoW — и реально для маленькой команды.

### 2.2 Что нужно

**Технологии**
| Что | Рекомендация | Зачем |
|---|---|---|
| Движок | Unreal Engine 5, **одна зафиксированная версия** для всех | Смена версии посреди проекта ломает ассеты |
| Сборка движка | **Из исходников** (GitHub Epic) | Без этого нельзя собрать выделенный сервер |
| Основа проекта | **Lyra Starter Game** (бесплатно от Epic) | Готовый сетевой шутер на GAS: стрельба, инвентарь, команды, UI |
| Геймплей | C++ (ядро) + Blueprints (тонкий слой настройки) | См. п. 3.3 — так Claude может работать максимально эффективно |
| Способности/статы | Gameplay Ability System (GAS) | Характеристики, навыки, эффекты, урон, баффы — всё по сети |
| Сеть | Dedicated Server, replication + Iris, серверная авторитетность | Защита от читов |
| Бэкенд | **Nakama** (open-source, есть плагин UE5) + PostgreSQL | Аккаунты, профили, инвентарь, рынок, гильдии, чат |
| Контроль версий | **Perforce Helix Core** (бесплатен до 5 пользователей) или Git + LFS с блокировками | Бинарные .uasset нельзя мержить — нужны блокировки файлов |
| Задачи | GitHub Projects / YouTrack / Jira / Notion | Бэклог, спринты |
| Ассеты | Fab (маркетплейс Epic), Megascans, MetaHuman, Mixamo | Команда из 5 не нарисует весь мир с нуля |
| Связь | Discord | Ежедневные короткие синки |

**Железо (на каждого)**: 32 ГБ ОЗУ минимум (64 для сборки движка), SSD NVMe 500+ ГБ под проект, видеокарта уровня RTX 3060+.

**Люди и роли**: см. раздел 5.

## 3. Как Claude помогает и как мы работаем

### 3.1 Что я делаю хорошо
- **C++ для Unreal**: геймплей, GAS (характеристики, навыки, эффекты), оружие, инвентарь, крафт, ИИ животных, сетевой код и репликация, сохранения, UI-логика.
- **Бэкенд**: серверные модули Nakama (Go/TypeScript), схемы БД, API рынка/гильдий/территорий, Docker-развёртывание.
- **Документы**: GDD, технический дизайн, канон, квесты, диалоги, описания предметов, локализация.
- **Данные и баланс**: таблицы предметов/оружия/навыков в CSV/JSON → импорт в DataTable; симуляция экономики на Python (инфляция, источники и стоки денег).
- **Инструменты**: Python-скрипты для редактора UE (массовый импорт, проверки ассетов), скрипты сборки (UAT/BuildGraph), CI.
- **Отладка**: разбор логов, крэшей, ошибок компиляции; код-ревью кода команды.
- **Управление редактором через MCP**: расставлять акторы, собирать блокаут уровней, создавать материалы/Blueprint-заготовки.

### 3.2 Ограничения (важно знать заранее)
- **Blueprints и .uasset — бинарные файлы.** Без MCP я их не вижу и не редактирую. Поэтому логику лучше держать в C++.
- **Я не делаю 3D-модели, анимации, звук и концепт-арт** (могу писать скрипты для Blender и промпты для генераторов, но арт — за людьми и ассетами).
- **Я не «чувствую» игру.** Ощущение стрельбы, темп, веселье проверяют только живые плейтесты — это ваша зона.
- **Каждая сессия начинается с чистого листа.** Память проекта — это `CLAUDE.md`, папка `docs/` и бэклог. Поэтому документация — не бюрократия, а то, что делает меня полезным.
- Компиляция и запуск происходят на вашем ПК: я могу запускать сборку через терминал, но тестировать в редакторе будете вы.

### 3.3 Рабочий процесс
```
1. Задача в бэклоге (что сделать + критерии готовности)
2. Claude: план → код C++ / скрипт / документ → компиляция → тесты
3. Человек: открывает редактор, подключает к Blueprint/уровню, проверяет в игре
4. Ревью (человек + агент-ревьюер) → коммит
5. Раз в 1–2 недели — общий плейтест и разбор
```
Принцип **«C++ — мозг, Blueprints — настройка»**: я пишу классы с параметрами (`UPROPERTY(EditDefaultsOnly)`), а дизайнеры в редакторе подбирают значения, модели и эффекты, не трогая логику.

## 6. План разработки

Сроки — ориентир для команды, работающей **частично (~15–20 ч/нед на человека)**. Каждый этап заканчивается **проверкой (gate)**: идём дальше, только если критерии выполнены.

### Этап 0. Подготовка (2–3 недели)
| Задача | Кто |
|---|---|
| Утвердить объединённый канон (Вариант 1 + правки Варианта 2) | Вы + Claude |
| Выбрать и зафиксировать версию UE5; собрать движок из исходников | Техлид |
| Поднять Perforce / Git LFS, правила веток и блокировок | DevOps |
| Создать проект на основе Lyra, собрать клиент + выделенный сервер | Техлид + Claude |
| Создать `CLAUDE.md` проекта, `docs/`, установить скиллы и MCP, настроить агентов | Claude |
| Завести бэклог и ритм встреч (синк 2× в неделю, плейтест раз в 2 недели) | Вы |

**Gate:** все 5 человек открывают проект, собирают его и заходят на тестовый выделенный сервер.

### Этап 1. Пре-продакшн (4–6 недель)
| Задача | Кто |
|---|---|
| `01_Канон.md` — мир, фракции, регионы, тон | Вы + Claude (`lore-keeper`) |
| Столпы игры (3–4 предложения, по которым режутся все спорные фичи) | Вы |
| Core loop: вылазка → бой/добыча → возврат → крафт/торговля → прогресс | Вы + Claude (`game-designer`) |
| GDD по системам: стрельба, характеристики, навыки, предыстории, инвентарь/вес, климат/одежда, профессии, экономика, гильдии, территории, смерть и потеря лута, PvP-правила | Вы + Claude |
| Технический дизайн: архитектура клиент/сервер/бэкенд, схема БД, античит | Техлид + DevOps + Claude (`network-programmer`) |
| Визуальный стиль: мудборд, референсы, список ассетов Fab | 3D/техарт + уровни |
| Объём MVP — что входит в вертикальный срез, что нет | Все |

**Gate:** GDD и TDD утверждены, бэклог прототипа расписан.

### Этап 2. Прототип «серый бокс» (6–8 недель)
Цель — ответить на вопрос **«весело ли?»**.
- Персонаж: бег, присед, выносливость, вес инвентаря (Claude + техлид)
- Стрельба: 4 оружия (пистолет, АК-подобная винтовка, дробовик, снайперская), отдача, баллистика, износ (Claude)
- Здоровье, травмы, аптечки, базовые характеристики через GAS (Claude)
- Инвентарь с весом, лут с тел и контейнеров (Claude)
- ИИ: стая собак, кабан (Claude + уровни)
- 1 серая карта ~1×1 км: поселение + завод + дорога (уровни, MCP-блокаут — Claude)
- Выделенный сервер на 16 игроков, PvP с потерей лута (техлид + DevOps + Claude)

**Gate:** 5 плейтестов внутри команды + 5–10 друзей; стрельба и вылазка ощущаются хорошо.

### Этап 3. Вертикальный срез (3–4 месяца)
Один район Пограничья в финальном качестве:
- Бэкенд Nakama: регистрация, профиль, постоянный инвентарь и деньги (DevOps + Claude)
- Хаб-поселение: торговец-NPC, мастерская, склад (уровни + Claude)
- 2 предыстории (Военный, Инженер), 4 характеристики, 2 ветки навыков (Claude + вы)
- Крафт: 1 цепочка оружейника (сырьё → заготовка → оружие) и ремонт (Claude)
- 5 квестов/контрактов, 1 событие (Claude `lore-keeper` + вы)
- Климат: холод + одежда, загрязнение + фильтр противогаза (Claude)
- 1 захватываемый объект (насосная станция) для гильдий (Claude + DevOps)
- Финальная графика района, анимации, звук, UI (3D/техарт + уровни)
- 32–64 игрока на сервер, базовый античит (серверная проверка попаданий)

**Gate:** демо, которое не стыдно показать; внешний плейтест 30–50 человек; решение о дальнейшем финансировании/формате.

### Этап 4. Альфа (6–9 месяцев)
- Всё Пограничье, несколько зон-серверов, переходы между ними
- Все 6 предысторий, все ветки навыков, профессии (оружейник, бронник, инженер, медик, торговец + доп.)
- Рынок между игроками, контракты, караваны
- Гильдии, территории с обслуживанием (сырьё, ремонт), ограничения монополии
- Репутация с 4 фракциями
- Античит, логирование, админ-панель, бэкапы
- Закрытые альфа-тесты по ключам

### Этап 5. Бета (3–6 месяцев)
- Баланс экономики (симуляции + данные тестов), нагрузочные тесты серверов
- Оптимизация, локализация (RU/EN), страница Steam, модель монетизации
